# Пайплайн «Граф денег»

## Порядок вычислений

```
loading -> graph -> features -> clusters -> roles -> priority -> structure.resilience -> viewer
```

Порядок важен: `roles` использует `cluster_id` и `clusters_bridged`, поэтому
кластеризация идёт раньше ролей. `priority` использует `role` и `role_score`.

## Добавить признак узла

1. Считайте его в `features.py` — функция должна возвращать `DataFrame` с колонкой `gid`.
2. Подключите в `build_features()` через `merge`, добавьте значение по умолчанию в `fill`.
3. Добавьте имя колонки в `EXPORT_COLUMNS` в `pipeline.py`, иначе признака не будет
   в выгрузке и его нельзя будет перепроверить.
4. Если признак участвует в ролях — добавьте его в фикстуру `node()`
   в `tests/test_mg_roles.py`, иначе юнит-тесты упадут с `AttributeError`.

## Добавить или изменить роль

Правила в `roles.py::_rules` проверяются **по порядку**, первое сработавшее побеждает.
Порядок — от самой содержательной роли к самой слабой.

Пороги идут в `config.py` с комментарием, откуда взялось число. Привязывайте
к распределению, а не к круглому значению:

```python
# in_deg: 1760 узлов имеют ровно одного плательщика; порог 5 отсекает верхние 2.3%.
CONSOLIDATOR_MIN_IN_DEG = 5
```

Расширять словарь ролей можно — ТЗ это разрешает при условии документирования.
Так появилась `terminal_unverified`. Задокументируйте в README, иначе роль
не засчитают.

## Собрать evidence

Не склеивайте строку вручную: лимит в 200 символов обрежет самое ценное,
потому что оно обычно стоит в конце. Используйте `text.compose()`:

```python
return role, score, compose([core, *extras], 200)
```

`compose` добавляет фрагменты по убыванию важности, пока они влезают.
Порядок задан в `roles.py::_extras`: прямой возврат денег, затем указание
на источник вне выгрузки, затем цикл, затем точка сочленения.

Числа обязательны. Формулировка «высокий скор» не проходит проверку жюри,
«получает от 11 разных плательщиков» — проходит.

Склонение числительных — через `text.count()` и `text.payers()`, иначе получится
«14 кластера» и «1 seed-клиентов».

## Проверить результат

```bash
make test
./run.sh && head -5 out/top_nodes.csv
```

Любая правка порога меняет распределение ролей. Смотрите топ-лист глазами:
если туда попал узел с одной транзакцией у порога 5 000 ₸ — уверенность в роли
не масштабируется объёмом, это баг.

## Ловушки датасета

Они разобраны в `CLAUDE.md` и закрыты тестами. Коротко: обход оборван на 4-м колене,
у seed занижены входящие, у 354 узлов исходящие превышают видимые входящие.
Ни один вывод не должен молча опираться на эти артефакты.

## Воспроизводимость

Многопоточный scipy даёт расхождения ~1e-16 в HITS, а `-0.0` отличается от `0.0`
в CSV. Поэтому все float округляются перед записью в `pipeline.py`.
Если добавляете новый артефакт в `out/` — проверьте, что два прогона дают
одинаковые байты, и допишите его в `test_runs_are_byte_identical`.
