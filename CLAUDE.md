# Граф денег — контекст для Claude Code

Инструмент восстанавливает структуру финансовой сети по транзакционному графу:
роли узлов, кластеры и ранжированный список «кого проверять первым».
Кейс хакатона HackAlem AI, владелец задачи — Freedom. Полное ТЗ: `docs/TZ.md`.

## Команды

```bash
./run.sh                    # полный пересчёт: parquet -> CSV + viewer.html, ~3 секунды
make test                   # 53 проверки
xdg-open out/viewer.html    # экран просмотра
moneygraph-ask "вопрос"     # AI-ассистент (работает и без ключа)
```

## Что нельзя ломать

Три решения держат защиту перед жюри. Каждое закрыто тестом — если тест упал,
вы сломали не тест, а логику.

1. **`terminal` не присваивается на 4-м колене.** Там обход оборван, отсутствие
   исходящих — граница выгрузки, а не поведение. Для таких узлов есть роль
   `terminal_unverified`. Тест `test_terminal_is_never_assigned_at_truncated_depth`.
2. **Seed никогда не `transit`.** Граф собран от seed по исходящим, их входящие
   занижены, коэффициент пропуска недостоверен. Тест
   `test_seed_nodes_are_never_classified_as_transit`.
3. **Координатор требует баланса потоков.** Узел, раздающий кратно больше видимых
   входящих, не собирает деньги — он вливает их извне выгрузки. Тест
   `test_coordinator_requires_balanced_flow_not_just_degrees`.

## Правила работы с кодом

**Пороги только в `src/moneygraph/config.py`.** В `roles.py` не должно быть ни одного
числа-константы. Каждый порог сопровождается комментарием, откуда он взялся
(перцентиль, распределение в данных).

**Числа считает код, формулировки — человекочитаемые.** `evidence` пишется для
аналитика без ML-образования: с числами, до 200 символов, собирается через
`text.compose()` по убыванию важности фрагментов.

**Формулировки — гипотезы, а не обвинения.** «Признаки консолидации», а не
«консолидирует преступные доходы». Это требование ТЗ, раздел «Осторожность
формулировок».

**Воспроизводимость обязательна.** Все шесть артефактов в `out/` должны быть
побайтово одинаковы между прогонами. Многопоточный scipy даёт шум порядка 1e-16,
поэтому float округляются перед записью. Тест `test_runs_are_byte_identical`.

**Хардкод запрещён ТЗ.** Никаких зашитых списков gid — только расчёт.

**Внешние источники запрещены ТЗ.** Не достраивайте атрибуты клиентов, которых
нет в данных (пол, возраст, доход, организация) — это будет считаться выдумкой.

## После любой правки порогов

```bash
make test && head -5 out/top_nodes.csv
```

Изменение порога меняет распределение ролей по всей сети. Смотрите глазами топ-лист:
если там появились узлы с одной транзакцией на 5 000 ₸ — порог сломан.

## Структура

| Модуль | Ответственность |
|---|---|
| `config.py` | все пороги и веса, с обоснованием |
| `loading.py` | чтение parquet, проверки целостности |
| `graph.py` | направленный граф и неориентированная проекция |
| `features.py` | признаки: структура, достижимость от seed, время |
| `structure.py` | циклы, точки сочленения, устойчивость сети |
| `clusters.py` | Louvain и гипотезы по кластерам |
| `roles.py` | правила ролей и сборка evidence |
| `priority.py` | ранжирование и объяснение ранга |
| `text.py` | склонение числительных, укладка в лимит символов |
| `viewer.py` | автономный HTML со схемой сети |
| `pipeline.py` | CLI: один запуск от parquet до выгрузок |
| `agent/` | AI-ассистент: инструменты над графом, промпты, валидатор ссылок |
| `cli.py` | CLI ассистента |

## Правила для ассистента

Ассистент — надстройка. Пайплайн и выгрузки не должны от него зависеть:
`run.sh` не требует ни ключа, ни интернета.

Модель ничего не вычисляет. Новый вопрос аналитика = новый инструмент
в `agent/tools.py` плюс его описание в `agent/llm.py::TOOL_SPECS`.
Тест `test_tool_specs_match_implementations` следит, чтобы списки не разъезжались.

Каждый инструмент возвращает gid, на которые можно сослаться. Валидатор удаляет
из ответа предложения с несуществующими узлами — без этого модель начнёт
выдумывать номера счетов, и доверять ответу будет нельзя.
