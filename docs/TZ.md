# ТЗ кейса (HackAlem AI)

Направление: аналитика и принятие решений / кибербезопасность и комплаенс.
Формат: командная разработка, 5 часов. Данные обезличены.
Владелец задачи: Freedom.

## Название

Граф денег: восстановление финансовой структуры организованной группы
по транзакционной сети.

## Проблема

AML-аналитику банка по итогам оперативной информации известен только нижний
уровень цепочки — конкретные клиенты, получавшие деньги, связанные с незаконным
оборотом наркотиков. Кто стоит выше, через кого прогоняют средства и кто ими
распоряжается, приходится восстанавливать вручную.

| Последствие | Масштаб |
|---|---|
| Ручная трассировка на 4 колена | часы работы на один узел |
| Основная часть сети невидима | известен 81 клиент, реальная сеть — 2 248 узлов |
| Блокируется только нижний уровень | организаторы восстанавливают инфраструктуру за дни |
| Приоритет проверки выбирается интуитивно | ранжирования нет |

## Пользователь

AML-аналитик подразделения финансового мониторинга банка второго уровня.

Сценарий: получает список клиентов по делу (81 gid) → загружает выгрузку
исходящих переводов на 4 колена → инструмент строит граф, считает метрики,
присваивает роли → аналитик видит схему сети → открывает топ-лист приоритетов
с обоснованием и формирует перечень на углублённую проверку.

## Вход

Три файла `.parquet`: 2 248 узлов, 3 119 рёбер, 4 840 транзакций,
период 2026-07-01 — 2026-07-31, разовая выгрузка. Схема — в `docs/DATASET.md`.

## Выход

Три CSV фиксированной схемы плюс экран просмотра.

**`nodes_roles.csv`** — строка на каждый узел: `gid`, `role`, `role_score` (0–1),
`cluster_id`, `priority_score` (0–1), `evidence` (до 200 символов, человекочитаемо).

**`clusters.csv`** — строка на кластер: `cluster_id`, `n_nodes`, `n_seed`,
`sum_kzt_internal`, `top_gids`, `hypothesis`.

**`top_nodes.csv`** — не менее 20 узлов: `rank`, `gid`, `role`, `priority_score`, `why`.

Словарь ролей (обязательный минимум, расширение допускается при документировании):

| Роль | Смысл |
|---|---|
| `consolidator` | аккумулирует средства от нескольких участников |
| `transit` | пропускает средства дальше, не удерживая |
| `distributor` | веерное распределение на много получателей |
| `terminal` | деньги приходят и остаются |
| `coordinator` | координирующий узел, кандидат в организаторы |
| `peripheral` | признаков роли не выявлено |

Допустимая задержка: полный пересчёт не более 5 минут.

## Must have

1. Воспроизводимый пайплайн: один запуск от сырых parquet до всех трёх выгрузок,
   без ручных шагов, на чистой машине.
2. Роль, `role_score` и непустой `evidence` у каждого из 2 248 узлов.
3. Критерии ролей задокументированы: для каждой роли формальное правило с порогом.
   Жюри называет 3 произвольных gid — команда за минуту объясняет роль.
4. Кластеризация: размер, число seed, оборот и гипотеза по каждому кластеру.
5. Топ-лист ≥ 20 узлов с обоснованием и экран со схемой сети, где видно
   направление потоков и роли. Жюри называет gid — команда находит его на схеме.

## Опционально

Учёт артефакта обрыва графа · временны́е паттерны · повторяющиеся маршруты
и возвратные потоки · детекция аномалий · оценка устойчивости сети ·
AI-ассистент аналитика · автогенерация карточки узла · оценка полноты данных.

## Ограничения

**Нельзя:** хардкодить результат списками gid; сдавать чёрный ящик без
объяснимого правила; обогащать внешними источниками и достраивать атрибуты
клиентов, которых нет в данных; требовать GPU, облако или платные сервисы.

**Обязательно:** объяснимость для аналитика без ML-образования; приватность
(данные обезличены); осторожность формулировок — выводы как гипотезы, а не
утверждения о виновности; пересчёт ≤ 5 минут локально; раздел в README о том,
что изменится при росте графа до ~1 млн узлов.
